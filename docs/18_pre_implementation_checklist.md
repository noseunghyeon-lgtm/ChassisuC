# 로직 생성 전 검토 체크리스트 (Pre-Implementation Gate)

> 실제 Stateflow/Simulink 로직 생성(.slx 상세 구현) 전에 확정해야 할 사항을 점검.
> 🔴 **차단(Blocker)** — 확정 전 구현하면 재작업 큼 · 🟡 **권장** — 지금 정하면 좋음 · 🟢 **구현 중/후 가능**.

| # | 항목 | 왜 차단인가 | 소관 |
| --- | --- | --- | --- |
| A1 | **S1→S2 인터록 조건 수** (4 vs 6 vs 이관분) | 입력 개수·가드 구조가 바뀜. 포트/신호 재배선 유발 | 정본 §3.3 (M01) |
| A2 | **테이크오버 B안 — 정본 §7 금지천이 예외** | §7(금지천이+DTC) 규칙 자체를 고쳐야 함. 상태머신 감시 로직 영향 | 기아 (Q-118) |
| ~~A3~~ ✅ | **E-Stop 결과 상태 = S6 확정** | ✅ 해소(C01). E-Stop → S6(FAULT_SAFE_STATE) 정식 확정. 임시/TBD 해제 | 「안전」 (C01) |
| A4 | **권한 모델** (2단조작 vs GuardSwitch 독립?) | 인터록 입력이 1개냐 2개냐가 갈림 | SRS-SYS-051 |
| A5 | **승차 검지 인터록 유무** | 입력(driver_present)·전이 신설 여부. 지금 없으면 나중에 구조 추가 | 「안전」+실차 (§6) |

> A1~A6은 **상태·전이·입력의 "구조"**를 바꾼다. 구현 후 바꾸면 모델 재배선+재검증 비용.
