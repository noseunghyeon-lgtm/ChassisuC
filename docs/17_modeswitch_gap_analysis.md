# 원격/수동 전환 설계안 vs 현재 설계 — 차이점 & 수정방안

> 「원격·수동 전환 제어 로직 개발」(전체 관리 프로세스 /2) 설계안을 현재 ChassisuC
> 상태머신 설계(`build_chassis_controller.m`, docs/01·08·10)와 대조. 차이·충돌·수정안 정리.
> 중요도: 🔴 충돌(즉시 결정) · 🟡 보완 · 🟢 일치.

---

## 1. S1→S2 인터록 — ★ 조건 수 불일치

| 항목 | 전환 설계안 (§3) | 현재 설계 (T05) | 판정 |
| --- | --- | --- | --- |
| 조건 수 | **정본 §3.3 = 4조건** | **6조건 AND** (`arm_*` 6개) | 🔴 **불일치** |
| ① RS 인증 | O (SRS-SYS-013) | `arm_rs_mutual_auth` O | ✅ |
| ② 2단 조작 | O (SRS-SYS-018) | `arm_rmc_2stage` O | ✅ |
| ③ 차속 0 | O | `arm_speed_zero` O | ✅ |
| ④ 기어 **P 또는 N** | O (P or N) | `arm_gear_park` (**P만?**) | 🔴 **P만 vs P/N** |
| 브레이크 답력 | **없음** | `arm_brake_pedal` 추가됨 | 🔴 설계안에 없음 |
| 브레이크 원격설정 | **없음** | `arm_brake_remote_set` 추가됨 | 🔴 설계안에 없음 |

**분석:** 현재 설계의 6조건은 전환 설계안의 정본 4조건과 다르다.
- 설계안: RS인증 + 2단조작 + 차속0 + 기어(P/N) = **4개**.
- 현재: 위 4개 중 브레이크답력·브레이크원격설정 2개를 **추가**로 넣음 (과거 다이어그램 M01 흔적).
- 설계안 §11-1(이관분)은 또 다르게 **P단만 + 브레이크/가속 미답입 + 차속0** (RS인증·2단조작 **없음**).

> **이것이 M01(점검표)의 재등장.** 세 소스가 조건이 다름:
> ① 정본 4조건, ② 현재 6조건, ③ 이관분(§11-1).

**수정안:** 정본 §3.3 **4조건으로 정렬** 권장. `arm_brake_pedal`/`arm_brake_remote_set`는
S2→S3 중립확인 단계로 **이동**(설계안 §4 조작기 중립과 취지 중복). 기어는 **P 또는 N**으로 완화.

---

## 2. 권한 모델 — Remote Panel 2단조작 vs MODE_CMD.GuardSwitch (🔴 미정)

- 설계안 §2: Remote Panel 2단조작(SRS-SYS-018)과 RS의 `MODE_CMD.GuardSwitch`가
  **같은 것인지 독립 2개인지 미정** → SRS-SYS-051.
- 현재 설계: `arm_rmc_2stage` 하나로만 표현 (2단조작). GuardSwitch 개념 **없음**.
- **수정안:** 권한 모델 확정 시 반영. 독립 2개면 `arm_guard_switch` 입력 **추가** 필요.
  - ⚠️ Q-56: 현 패널 토폴로지(K31 MN/K34 RM 풀업)로 **2단조작 전기적 성립 불가** →
    `arm_rmc_2stage` 자체가 현재 HW로 미충족. 핀맵(docs/16)의 K31/K34와 연결됨.

## 3. S2→S3 조작기 중립 — 🟡 기준 미정의

| 항목 | 전환 설계안 (§4) | 현재 설계 (T07) | 판정 |
| --- | --- | --- | --- |
| 가드 | 모든 조작기 중립 + 첫 유효명령 | `actuators_neutral && first_valid_cmd` | ✅ 구조 일치 |
| 중립 기준 | 제동/가속/조향/기어 데드존 (임계 TBD) | `actuators_neutral` 단일 boolean | 🟡 **세분화 안 됨** |

**수정안:** `actuators_neutral`을 전처리에서 4개 조작기(제동/가속/조향/기어) 데드존 AND로 산출.
임계값은 TBD(RS 조작기 사양). 미중립 시 **어느 조작기인지** 조종자 표시 → `neutral_fault_mask` 출력 추가 검토.

## 4. 제어권 이양(무충격) — 🟢 대체로 일치

| 방향 | 전환 설계안 (§5) | 현재 설계 | 판정 |
| --- | --- | --- | --- |
| S1→S2 제동 | 페달 위치 캠 정합 후 위치0 램프다운 | T05 액션(캠 정합) 설계문서에 명시 | ✅ |
| S2→S1 제동 | 캠 원점 복귀 후 무여자 | T06 `cam_at_origin` 가드 | ✅ |
| 조향 | 여자 시 현재 각 목표 | docs 반영 | ✅ |
| 가속 | 0부터 시작, 직전값 상속금지 | docs 반영 | ✅ |
| 변속 | 여자 상시 유지, 입력원만 전환 | S1 예외(§1.3) 반영 | ✅ |

→ 무충격 이양은 **잘 일치**. 코어 스크립트는 가드만, 액션 상세는 설계문서/사용자 구현 영역.

---

## 5. 사람·차량 분리 (승차 검지) — 🔴 현재 설계에 전무

- 설계안 §6: 원격주행 중 **승차 검지 인터록이 없음** (정본 §3.3에도 없음). 인적 사고 위험.
- 현재 설계: **동일하게 없음**. 운전자 재석 검지 입력/전이 **미존재**.
- **수정안:** 검지 수단(시트/도어/버클 스위치) 확정 후 입력 추가. 검지 시 **원격명령 거부 후 정차**
  (즉시 S6는 과함 — 설계안과 동일 판단). 신규 입력 `driver_present`, 동작은 `remote_cmd_lock` + 정차 유도.

## 6. 전환 실패/이상 처리 — 🟡 부분 반영

| 케이스 | 전환 설계안 (§7) | 현재 설계 | 판정 |
| --- | --- | --- | --- |
| S1→S2 중 조건상실 | S1 복귀, 부분여자 금지 | T05 실패시 S1 복귀(설계문서) | ✅ |
| 액추에이터 여자실패 | 순서대로 되돌림 + DTC | 설계문서 언급 | 🟡 코어 미구현 |
| **MODE_CMD 미수신 500ms** | 현 모드 유지(자동 하강 안 함) | **없음** | 🔴 미반영 |
| **인증 만료** | S3→정차→S2, S2→S1 (즉시 끊지 않음) | **없음** | 🔴 미반영 |
| 2단조작 1단만 | 3초 자동 해제 + 경고 | `arm_rmc_2stage`에 암묵 | 🟡 타이머 미구현 |
| S3→S1 직접 | 거부 + DTC (금지천이) | §7 미생성으로 차단 | ✅ |

**수정안:** `mode_cmd_age_ms`(미수신 감시), `auth_valid`(인증 만료) 입력 추가.
- 인증 만료: S3면 정차 유도 후 S2, S2면 S1 (주행 중 즉시 끊기 금지) — **신규 전이/로직**.

## 7. 테이크오버 — 🔴🔴 정본과 정면 충돌 (Q-118)

- 설계안 §11-3(이관분): 운전자가 조향/제동 조작 → **S3→S1 직접 복귀**(테이크오버)를 정상 수단으로.
- 현재 설계 + 정본 §7: **S3→S1 직접은 금지천이** (DTC 발행, 원천 차단).
- **정면 충돌.** 둘 다 임의 수정 불가.
- 트리거: 조향 조작 / 제동 중 모터토크 매우 작음(=운전자 페달) → 임계값 TBD.
- 가속 밟으면 **"안전 정지 모드"**(S0~S6에 없는 새 이름 → Q-121).

**수정안 (택1, 사용자·기아 확정):**
- **A. 경유 재설계**: 테이크오버 → S3→S2→S1 경유 (금지천이 유지). 안전하나 즉시성 ↓.
- **B. 금지천이 예외**: S3→S1에 "테이크오버" 조건부 허용 (정본 §7 + 본 설계 둘 다 개정).
- **C. 안전정지모드 신설**: 테이크오버 시 전용 상태(감속→정지→P). Q-121을 S7 등으로 등재.

> 이건 **"원격주행 중 운전자가 개입할 수단이 있는가"**라는 안전 핵심 질문. 가장 중요.

## 8. 수정 방안 요약 (우선순위)

| # | 항목 | 수정안 | 결정 주체 |
| --- | --- | --- | --- |
| 1 | **S1→S2 조건 수** | 정본 4조건으로 정렬, 브레이크 2조건은 S2→S3로 이동, 기어 P/N | 정본 §3.3 확정 |
| 2 | **테이크오버 충돌** | A/B/C 중 택1 (경유 vs 예외 vs 신상태) | 사용자+기아 (Q-118/121) |
| 3 | **권한 모델** | 2단조작 vs GuardSwitch 독립성 | SRS-SYS-051 |
| 4 | **승차 검지** | driver_present 입력 + 명령거부·정차 | 「안전」+실차 |
| 5 | **MODE_CMD/인증 만료** | 미수신500ms·만료 처리 전이 추가 | 본 설계 반영 |
| 6 | **중립 기준** | actuators_neutral 4조작기 세분화 | RS 사양 |

> 🟢 무충격 이양(§5)은 현재 설계와 잘 일치. 수정 불필요.

## 9. 즉시 반영 가능한 것 (스크립트)
- S1→S2 가드를 **정본 4조건**으로 정렬 (브레이크 2조건 제거 or S2→S3 이동).
- `mode_cmd_age_ms`, `auth_valid`, `driver_present` 입력 **골격 추가** (전이는 정책 확정 후).
- 테이크오버/권한모델은 **결정 전까지 미반영**(충돌 사안).
